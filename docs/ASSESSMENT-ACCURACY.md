# Assessment accuracy and score contract

The default evidence pipeline is enabled by `FACT_CHECK_ENHANCED_ENABLED=true`. `FACT_CHECK_QUEUE_ENABLED` selects synchronous or queued execution. It uses the existing provider and model settings in `config/services.php` and bounded retrieval settings in `config/fact_check.php`; no additional API key is required. The Laravel queue worker is required when queueing is enabled. The legacy path remains available to read historical reports. Historical JSON is not migrated or given a fabricated percentage.

## What changed

An upload is preserved as the original media. Inline event-verification questions retain their verbatim proposition, including user spelling, for factual research. A named event in a photograph is checked as a factual/provenance question; AI-generation scores cannot establish the pictured identity or event. Unknown provenance produces an Unverified factual finding after the available searches, rather than a follow-up task-selection question. Automatic bare-photo checks complete media screening when no factual text is available; readable news content still follows the factual route. Historical task-choice reports display a read-only incomplete finding without asking another question. Retry limits are isolated by user and report; HTML retries above the limit return to the saved result with a cooldown message, while JSON clients retain an explicit 429. The selected mode, leading user questions, and extracted content are used to select the main task. Explicit questions take priority. A news screenshot with OCR text can be checked as a claim even without a typed caption. Separate AI-generation, manipulation, factual and context requests produce separate assessments. General editing detection is unsupported; the AI-generation CNN cannot substitute for it. A completed CNN output does not establish image provenance or factual truth.

OCR lines are joined into paragraphs before claim planning. Whole-post references, attribution and qualifiers are retained. A factual claim can be searched even when its date is unknown, while unreadable words are reported. Discovery uses the configured Google Fact Check, GNews and NewsAPI services and reviewed page text. A generic homepage, search result or snippet cannot supply a decisive relationship. Search and page budgets and a bounded second round still apply. A claim-source relationship requires a contiguous cited passage plus matching event, actors, action, date, place, quantities and qualifiers. A contradiction is required for False. Different supported and refuted claim components are needed for Partly True. Unresolved opposing passages yield Conflicting Evidence. Retrieval errors and unreadable input are processing statuses. The result stores provider attempts and an outcome reason.

Context findings require a reviewed passage, an exact submitted quote and matching subject. Outdated also requires an explicit validity passage, expiry date and claim wording that presents it as current. Publication age alone is insufficient. A source can establish a misleading caption or explicit satire label, but the application has no general visual provenance, reverse-image or editing detector. Such determinations are limited by what reviewed text can establish. An embedded factual assertion still has its own claim assessment.

`assessment-v4` is the new verdict vocabulary. Historical verdicts, including `UNVERIFIABLE` and `NO_STRONG_AI_SIGNAL`, remain readable. API JSON, saved detection results and report cards use the same v4 verdict and score for new evidence-pipeline results; the history presenter reads that stored result. The legacy `fake_score` database column is still a screening/risk field for earlier dashboards; it is not a fact-check confidence and never drives a v4 verdict percentage. The canonical cache key includes the request task/question, model identity, source snapshot, cutoff, pipeline and score versions. Search/page caches have the configured short TTL. A changed input or evidence snapshot produces a new result; old records are not rewritten.

## What the percentages mean

A **model score** is available only for an image when the inference adapter validates a two-class sigmoid contract with `real=0`, `fake=1`, a `fake` positive output, valid preprocessing/model shape, and a finite output in [0,1]. The displayed number is the raw fake-class score for Likely AI-Generated and `1 - raw fake-class score` for Likely Not AI-Generated. The score is uncalibrated. The raw output, class map, model hash, threshold and preprocessing stay in details. A video top-k frame aggregate has no validated whole-video percentage, so its score is unavailable. Missing, invalid or incompatible model outputs have no percentage.

The original CNN image configuration records RGB input, a 224×224 tensor and the `0_to_255_float32` range with model-internal MobileNetV2 preprocessing. The adapter checks these dimensions, range, sigmoid activation and label map against the loaded model. The full training-time resize/orientation pipeline is not bundled, so exact preprocessing equivalence and probability calibration are not established. The small provenance smoke set includes a known AI image that the original CNN misses; no threshold is changed based on that set.

An optional offline image-origin specialist is enabled with `AI_ORIGIN_ENABLED=true`. It uses the pinned [Bombek1 SigLIP2 + DINOv2 release](https://huggingface.co/Bombek1/ai-image-detector-siglip-dinov2), with bundled preprocessing and strict checkpoint loading. The original image CNN still runs on the same persisted upload; both findings are saved and disagreement is shown. Their scores are never averaged. The separate `.venv-ai-origin` runtime preserves the existing TensorFlow, text and video environments. The pinned installer and setup commands are in `automation/deepfake-models/install_ai_origin.py`; large weights and the virtual environment are excluded from Git.

The specialist retains its published 0.5 decision threshold and unchanged weights. A separate provisional `origin-selective-v1` reporting rule returns Inconclusive with no percentage when the larger class score is below 0.9. This is an abstention rule selected using six development controls, not a validated confidence threshold. The rule was frozen before three held-out controls were obtained. Specialist failures retain the original CNN finding but produce a partial, inconclusive origin report.

The fresh nine-control smoke check recorded seven correct and two incorrect raw specialist labels; after the abstention rule, six findings were decisive and correct and three were inconclusive. Held-out controls alone yielded one correct decisive finding and two inconclusive findings. A newly generated house remained inconclusive. On the same six development controls the original CNN classified three correctly and the specialist five correctly. These small, nonrepresentative checks do not establish deployment accuracy, calibration, or general improvement. All inputs, provenance links, raw errors, file hashes and outcomes are saved in `output/validation/ai-origin-smoke-2026-10-15/results.json`, with a readable `report.html` and real-application upload records in `application-uploads.json`. Saved historical answers were not used as ground-truth labels.

**Evidence strength** uses `evidence-strength-v1`, a provisional engineering rubric for resolved True, False and Partly True claim assessments. For each required factual claim, a validated stance-specific passage gets 25% exact relevance, 25% direct passage, 20% source suitability, 10% temporal match, 10% geographic match, and 10% independent corroboration. A primary record from the relevant official, institutional or research source counts as suitable and sufficient corroboration; a fact-check gets 80% of suitability, direct reporting 60%. An undated record gets half temporal credit. Two different unflagged publisher hosts or a relevant primary record earn corroboration credit; suspected copies do not. The best passage supplies each claim's score; the minimum claim score gives the report score so incomplete coverage cannot be hidden by stronger claims. The score stores component values and source IDs. Source-type and exact-match judgments still depend on the reviewed passage and have not been validated against a representative human-labeled set. Host diversity is only a conservative proxy for independence. The rubric is not a probability, measured accuracy or statistical confidence. A high score next to False describes support for that False assessment. Missing, conflicting, contextual, technical and inconclusive assessments have no percentage. Score decisions use unrounded values; display rounds only at the end and uses `>99%` or `<1%` at extremes to avoid implying certainty.

There is **no calibrated Confidence percentage** in the current deployment. Historical model-authored numeric estimates are retained only as historical diagnostics; they are not shown as new percentages. A future calibrated probability would require task-specific human-reviewed calibration data, validation on a separate held-out set, and versioned deployment of the calibrator. The report's details include the score method and its limitations.

The calibration implementation now supports `binary-temperature-v1`: positive temperature scaling of the logit of the raw sigmoid score, clipped to [0.000001, 0.999999] before the logit. It preserves the original model's class ordering, labels, weights and decision threshold. It does not improve classification accuracy by itself. The method follows [temperature scaling](https://proceedings.mlr.press/v70/guo17a.html); fitting data must be separate from training and final evaluation, as explained in the [calibration documentation](https://scikit-learn.org/stable/modules/calibration.html).

`automation/evaluation/capture_image_calibration_scores.py` captures fresh, offline predictions from the pinned specialist for reviewed original images, verifying each original hash before and after inference. `calibrate_image_scores.py` fits only the calibration split, then records held-out log loss, positive-class Brier score, reliability bins, ECE, and a paired cluster-bootstrap log-loss difference interval. Export as `validated_on_supplied_population` requires at least 100 independent groups of each class in each split, a finite interior fit, and held-out improvement; otherwise the artifact remains `fitted_not_validated`. This engineering gate is not proof of universal calibration. Do not reuse the test set to select methods after failure. Real population/prevalence suitability and exclusion of the model's training images require documentary review; metadata fields cannot establish them on their own.

`MEDIA_CALIBRATION_ENABLED` remains false by default. Enabling requires a validated artifact path and its exact SHA-256 in `MEDIA_CALIBRATION_SHA256`. `MediaScoreCalibration` checks the model, preprocessing/config and adapter identities, validation status and independent sample counts before applying it. Invalid, changed, missing, insufficient or incompatible artifacts retain the uncalibrated model score. The stored calibrated score retains the original raw score, calibration hash and validation scope. Inconclusive and unavailable assessments still have no percentage. Old reports are not retroactively recalibrated. No live artifact was fitted from the nine-image smoke check: those images do not meet the calibration requirements.

## Evaluation protocol

Run `python automation/evaluation/evaluate_assessments.py --template annotations.jsonl` for the schema. Annotate independently reviewed examples as JSONL with a factual, AI-generation, manipulation or context task, the relevant class label, `event_group`, duplicate/media/near-claim groups where applicable, review identity and date, evidence URLs or media provenance, cutoff and a fixed split. Prediction JSONL needs the same `case_id`, `task` and cutoff, plus a frozen `verdict`; record technical failures and inconclusive results explicitly. Use `--annotations annotations.jsonl --predictions before.jsonl after.jsonl --output report.json --diagrams diagrams` to compare systems on exactly the same test cases. Each task has a separate confusion matrix, class precision/recall/F1 and support, error list, abstention counts and coverage. Valid class probability vectors also produce Brier score, log loss and reliability bins/diagrams. The code checks event/media/duplicate groups and near-identical text for split leakage. The reliability calculation follows the standard distinction between predicted score and observed frequency described in the [scikit-learn calibration guide](https://scikit-learn.org/stable/modules/calibration.html).

For binary media tasks, `--fit-calibration ai_generation` or `--fit-calibration manipulation` reads **only** calibration-split predictions and outputs isotonic fit blocks marked `fitted_not_validated`. This is evaluation tooling; it never changes deployed model output. Fit on separate calibration data, then test on the untouched final split. The supplied examples under `tests/Fixtures` are small provenance or regression fixtures, not a representative held-out human-reviewed accuracy dataset. The training config metrics are training artifacts and are not substituted for a new benchmark. Without a suitable held-out set, no before/after accuracy, class F1 or calibration improvement can be claimed.

Run the PHP feature/unit tests, `python -m unittest discover -s automation/evaluation -p 'test_*.py'`, and `node tests/browser/assessment-report.mjs` after rendering its view fixtures. `truthguard:evidence-doctor --live` checks bounded live connectivity, not factual correctness. Tests using `Http::fake()` prove routing, citation and failure behavior only; they are not successful live integration checks.
