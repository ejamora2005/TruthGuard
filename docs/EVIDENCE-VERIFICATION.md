# Evidence verification implementation

Implemented October 13, 2026. This is a software and integration improvement; a fact-checking accuracy improvement has **not** been measured.

## Inspection and request trace

The application uses Laravel, Blade, Alpine/Livewire, the existing detection table, and JSON canonical results. An authenticated submission reaches `DetectionController::store`, validates the submission, and calls `DetectionPipeline::run`. The pipeline stores the media and runs the existing manipulation model separately. The enhanced branch then runs:

1. `SubmissionExtractor`: retain supplied wording, visible OCR, inferred interpretation, sampled-frame coverage, and retrieval failures separately.
2. `ClaimPlanner`: identify exact quoted assertions, entities, dates, and qualifiers; distinguish opinions, predictions, questions, and rhetorical/unclear headlines.
3. `ArticleSearch` / `SafeArticleFetcher`: discover candidates, retrieve permitted full text, preserve dates/status, group copies, and filter the evaluation cutoff.
4. `EvidenceJudge`: validate structured claim/source IDs, matching excerpts, relevance dimensions, and explicit dated supersession.
5. `EvidenceVerificationService`: aggregate claim outcomes, record limitations/model diagnostics, and save a versioned canonical result. The detection retains its owner, original media, and normal result URL.

The optional queue creates the owned report before work starts, then updates that same row through real stages. Result JSON and the Blade page show queued/processing/failed states without manufacturing a verdict. Opening an existing completed report preserves its saved assessment unless the existing refresh behavior is explicitly invoked.

The previous path could lose relevant evidence through a seven-day news window, limited searches, and weak coverage of full article text. Matching related election keywords did not establish matching events, dates, or actions. Inferred image descriptions could also obscure the visible wording. The legacy `18/100` value was requested from the language model, with rule-based caps (49 for unverifiable and 69 for partly true); it was neither a calibrated probability nor measured accuracy. Version 2 removes that numeric factual score. Old values remain in saved data and are disclosed only as legacy diagnostics.

## Evidence and verdict rules

- Exact input and OCR are retained. A vision interpretation is never substituted for the visible words. Unclear or incomplete wording requests context. Inputs over 24,000 characters are not silently cut into a different claim.
- At most six atomic claims are planned. Reaching that cap produces a coverage limitation. English/Filipino variations retain the original meaning; providers retain their supported language settings.
- Supported/refuted requires an approved, retrieved source and a validated matching excerpt. Search snippets, publisher reputation, an API rating of a different claim, and model class scores cannot independently establish a verdict.
- `Mixed` requires distinct supported and refuted claims. Unresolved support/contradiction for the same claim abstains. A later source resolves earlier evidence only through an explicit, dated superseding passage. Superseded records remain in diagnostics and do not count as current decisive sources.
- One direct primary record can suffice; there is no minimum article count. A petition is not a final court ruling, and a proposed bill is not an enacted law. These safeguards supplement, rather than replace, semantic review.
- Publication/update dates later than the evaluation cutoff are excluded. Undated pages are excluded from historical evaluations. The cutoff, assessment time, and original claim date when verifiably supplied are recorded. No missing date is invented.
- The report uses categorical evidence strength with reasons. Its `confidence` is null. Media manipulation, NLP class output, evidence sufficiency, and measured system accuracy remain distinct.
- The existing result layout is retained: submitted content first in document/mobile order, verdict above the quoted claim, sources/findings, limitations, and expandable diagnostics. No “Claim Assessment” heading or global report-number prefix is reintroduced.

Result counts have different meanings: **results found** counts provider discoveries (including repeats); **unique articles reviewed** counts distinct sources with validated relationship records; **sources used** counts distinct current sources supporting or contradicting the factual assessment. Downloading a page alone does not increment reviewed/used. Raw retrieval counts are also stored.

Requests are sequential (concurrency one), without automatic retries. A provider 429 starts a bounded shared cooldown. At most three structured calls are made: decomposition and up to two evidence passes. Media OCR can add one separate call. Structured replies respect the existing `OPENAI_MAX_COMPLETION_TOKENS` setting, additionally capped at 5,000; OCR is capped at 2,000 and the same existing setting. Large/incomplete structured responses fail closed rather than silently increasing cost. Article text shares the model input budget; partial readings are recorded and cited passages must occur within the text actually supplied. Model, OCR, CNN, and extraction stages have their own timeouts; the retrieval window is **not** an end-to-end latency guarantee. The existing monthly-token setting is a dashboard estimate, not a hard billing cap.

Remote fetching validates every redirect, rejects private/local/reserved addresses, pins a validated public DNS address for cURL, disables proxy/automatic redirects, and limits bytes/types. It checks robots/access restrictions and does not bypass paywalls. Only HTML, plain text, and selectable PDF text are read. PDF extraction is capped at 30 pages. At this October 13 stage, no new search provider or credential had been introduced; the later OpenAI web-search addition is described below. Existing weather/feed/social integrations remain in their respective legacy/features code; the enhanced claim verdict does not use a current weather forecast or social snippet as proof of a historical claim.

## Trained models and live checks

The bundled NLP checkpoint is a DistilBERT article classifier with the project's existing `0 = Likely Real News`, `1 = Likely Fake News` mapping. Inference preserves existing whitespace normalization and the bundled cased tokenizer. Its default window is 256 tokens, capped by the architecture's 512 positions. Short inputs are unsuitable for an article-level verdict; overlong inputs now return `unsuitable_long_input` with no substituted truncated prediction. It reports weight SHA-256, raw class scores, task, scope, token count, and availability. The unchanged 0.70 uncertainty threshold is an existing heuristic, not a new calibration result.

The repository describes a Filipino training task, but complete training provenance, language-specific held-out labels, and independent validation artifacts were not available to reproduce its claimed performance. The older README's macro-F1 and CNN configuration metrics are historical claims, not measurements of this fact-checking pipeline. No cross-language accuracy is asserted. The trained classifier supplies an explicitly separate diagnostic; evidence determines factual outcomes. Any disagreement is retained. Image/video CNN results concern manipulation and have no authority over factual truth.

## Setup and rollback

1. Use the existing PHP/Python environments and credentials. Required key names are `OPENAI_API_KEY`, `GOOGLE_FACT_CHECK_API_KEY`, `GNEWS_API_KEY`, and `NEWSAPI_API_KEY`; do not put keys in frontend code. Enabled stages are controlled by existing `OPENAI_ANALYSIS_ENABLED`, `OPENAI_CLAIM_EXTRACTION_ENABLED`, `LIVE_VERIFICATION_ENABLED`, and `TRUTHGUARD_NLP_ENABLED` settings.
2. Run `php artisan migrate`. The new pending-report migration only permits null `analyzed_at`; it does not rewrite saved reports. Both result migrations are already applied in this local workspace. Ensure the existing public storage link is present.
3. Run `python automation/nlp/transformer_api.py` using the environment with `automation/nlp/requirements-transformer.txt` installed. Keep `TRUTHGUARD_NLP_URL` pointed at its private/local endpoint. In production, supervise this service. Make `pdftotext` available or set `FACT_CHECK_PDF_BINARY` to its absolute path.
4. Keep `FACT_CHECK_ENHANCED_ENABLED=true`. Run `php artisan config:clear` after local environment changes (rebuild the configuration cache according to deployment policy).
5. Check `php artisan truthguard:evidence-doctor` without network usage, or `php artisan truthguard:evidence-doctor --live` for small real API requests. The live option consumes provider quota. `php artisan truthguard:models:health --load --json` loads actual models.
6. Optional background mode: start `php artisan queue:work evidence --queue=evidence --tries=1 --timeout=300` under the deployment supervisor, then set `FACT_CHECK_QUEUE_ENABLED=true`. The dedicated database connection has `retry_after=360`. Default remains false so submissions do not become stranded without a worker. Configure process timeouts for the selected media models.

To roll back routing, set `FACT_CHECK_ENHANCED_ENABLED=false` and `FACT_CHECK_QUEUE_ENABLED=false`, clear/rebuild configuration, and restart long-lived workers. Drain already queued evidence jobs before switching code/configuration. Keep the JSON data and backward-compatible columns; existing version 2 reports remain readable. Do not use `migrate:fresh` or delete canonical results. The nullability migration refuses to reverse while pending/failed rows have no assessment date; finish or explicitly resolve those records rather than inventing timestamps.

The tiers attached to this application's keys have not been confirmed, so these limits are a plausible coverage explanation, not an observed account restriction. Broader queries and the domain filter cannot supply older articles when a plan does not expose them. An archive-capable general document index or access to an appropriate provider archive would be needed for that case.

The browser fixture passed six result variants at desktop, tablet, and mobile widths, checking source visibility, citations, score labels, overflow, and interactions; Blade templates compiled. No replay or provider request was made after that rejection, and no retrieved source or revised Leyte verdict is claimed.

Semantic relevance and extraction still depend on a fallible language model; schema/excerpt validation is not a formal proof of entailment. Search-index coverage, approved-host policy, short text windows, plan limits, robots/paywalls, duplicate-detection heuristics, and missing historical archives can cause abstention. Exact normalized copies are excluded; near copies are flagged as possibly shared reporting and retained because a changed negation, date, or action could be material. They must not be counted as independent confirmation. PDFs are text-only and videos use sampled frames without audio transcription. Current copies of older undated/untracked edits cannot establish historical truth reliably. A recorded posting date is not by itself a historical assessment: run an explicit dated evaluation separately.

There is no trustworthy independently reviewed claim-level held-out set in this checkout. Accuracy, calibration, before/after gains, retrieval relevance, and citation correctness remain **unmeasured** until human annotations and frozen predictions are supplied. Use the evaluation guide; do not interpret software tests or model-load success as accuracy evidence.

## GNews live diagnosis (October 14, 2026)

The registered command is `truthguard:evidence-doctor --live`. It and the default enhanced production route both call `Evidence\ArticleSearch`; the legacy route used when `FACT_CHECK_ENHANCED_ENABLED=false` has separate integrations. The smoke query uses the public terms `Philippines public information`. Its GNews request used quoted terms, `lang=en`, `max=3`, a UTC `to` cutoff, and `sortby=relevance`, all documented [search endpoint parameters](https://docs.gnews.io/endpoints/search-endpoint).

The actual GNews response was **HTTP 200**, `application/json; charset=utf-8`, with fields `information`, `articlesRemovedFromResponse`, `totalArticles`, and `articles`; it had `totalArticles=38`, `articles=[]`, and no error field. The sanitized provider notice said three page articles were removed because historical data beyond 30 days requires a paid plan, and Free data has a 12-hour delay. GNews [documents](https://docs.gnews.io/json-response) the total as all matches and `articles` as the returned page; its [FAQ](https://gnews.io/faq) describes Free archive removal and freshness delay. This was an account-coverage limit, not malformed JSON, an authentication failure, or an invalid query. A second public query for `Philippines`, bounded to the preceding seven days and sorted by publication time, returned three articles over HTTP 200, confirming the account can return accessible news.

`ArticleSearch` previously required a nonempty GNews `articles` array when `totalArticles` was positive, producing the misleading `invalid_response`. It now accepts that documented shape, records `archive_limited` when historical articles were removed from an empty page, and retains the returned total, removal count, freshness delay, HTTP status, content type, response field names, and sanitized error in attempt diagnostics. Genuine empty pages without a provider limit remain `ok`; malformed pages remain `invalid_response`. GNews HTTP 400 is `invalid_request`, 401 is `authentication_failed`, 403 is `quota_or_subscription_limited`, and 429 is `rate_limited`, consistent with [GNews error handling](https://docs.gnews.io/error-handling). The diagnostic prints this adapter metadata and never prints keys or authorization headers. An archive-limited search alone does not produce a false verdict; the report explains the coverage gap.

The post-fix live diagnostic returned Google Fact Check **HTTP 200 / ok**, GNews **HTTP 200 / archive_limited** (38 total matches, zero returned, three removed, 12-hour delay), NewsAPI **HTTP 200 / ok** (three returned), and OpenAI **structured_response_completed**. The NLP connectivity probe completed; this is not an accuracy measurement. This result is intentionally more specific than turning the GNews line green.

# Verdict groups and independent assessment paths

`AssessmentVerdict` defines the shared factual, context and media vocabulary. A factual result is True, False, Partly True, Misleading, Unverified or Conflicting Evidence. Context findings include Outdated, Out of Context, Missing Context, Satire / Parody and Opinion / Not Fact-checkable. Processing failures remain separate from these findings. Public JSON records `assessment_group`; result pages, history and notifications use the same validated labels.

Misleading requires a reviewed passage establishing the inaccurate impression. It is not a synonym for a false claim, an AI-generated image or missing search results. Outdated requires current framing and an established expired validity period, not simply an old article date. Out-of-context and satire findings require saved reviewed sources and valid citation IDs; satire additionally needs explicit satire/parody provenance. An opinion can still be accompanied by independently checkable factual statements. Context checks can research provenance even when the literal wording is non-factual.

Combined requests preserve factual, context and origin findings separately. A failed contextual check cannot erase a supported factual claim, and a low AI-origin signal cannot establish a factual event. When satire cannot be established, an independently identified opinion classification remains visible. The general manipulation categories are supported by the contract, but the current image-origin models do not establish general editing: requests requiring an unavailable manipulation analyzer remain Unsupported Analysis. Confirmed AI generation also requires stronger provenance than an uncalibrated model signal.

Evidence analysis uses `FACT_CHECK_MODEL_OUTPUT_TOKENS` (default 5000, bounded at 12000) separately from the shorter generic report budget. This prevents multi-claim/source JSON from being cut off by the generic 1400-token cap. Truncated responses are recorded as incomplete and never accepted as complete evidence. This changes request capacity, not trained model weights or factual labels.

Fresh diagnostic inputs and archived execution records are in `output/validation/misinformation-2026-10-15/`. They do not use previous user results as labels and do not constitute an independently reviewed accuracy benchmark. Blocked publishers, robots restrictions and HTTP 429 responses still limit real discovery; these cannot be replaced with snippets or assumed matching evidence.

See `automation/evaluation/README.md` for fresh capture, independent review and per-task/verdict calibration. Confidence is disabled until a compatible validation artifact passes its gates; the provisional evidence rubric is not calibrated confidence.
