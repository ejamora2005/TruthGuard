# Explicit AI-check routing

`SubmissionTask::VERSION` is now `tasks-v12`. Direct requests to check AI origin
take priority over a generic selected Fact Check mode or a pasted fact-check
guide. The previous parser focused on leading questions and could miss an AI
request after another sentence or after a long guide.

Examples routed to media analysis include:

- `check if ai generated`
- `Analyze whether the attached image was generated by artificial intelligence.`
- `Here is my upload. Please check if it is AI generated.`
- A fact-check guide followed by `Check if this is AI-generated.`
- A generic guide in the caption and an AI-check request in notes.

The router separates known guide prefixes from the user's actual request,
recognizes direct origin-check instructions in English and Filipino, and stores
the actual request in the report. The detector-only path does not run OCR,
claim decomposition, source discovery or article fact checking. Routing itself
is deterministic and adds no model request. Existing optional media explanation
behavior is unchanged.

Separate explicit requests still remain separate tasks. For example, asking
both whether the image is generated and whether a statement is true retains
both assessments, with media analysis as the primary task. A negated detector
instruction or a factual news question merely mentioning AI does not request
the detector. OCR and fetched article text never control this instruction check.

The regression run passed **193 tests with 1,560 assertions**, including upload
tests that assert no text/research HTTP requests are sent for AI-only prompts.
Tests also preserve factual/context questions, mixed tasks and existing guides.
An older health-query fixture now specifies its Philippine scope, and the
current-status query branch only applies when its flag is actually true.

Saved reports were not rechecked or rewritten. New submissions use the revised
routing version, which also changes request reuse identity.
